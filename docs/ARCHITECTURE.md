# Mg2Si 数据与主动学习架构

## 1. 分层模型

项目采用“原始源 -> 规范化层 -> 工艺-状态-生物模型 -> 安全约束优化 -> 实验反馈”的结构：

```text
材料库 Excel                 TACE Excel
      |                           |
      +------ 规范化与映射 --------+
                    |
          material/cell/stage 长表
                    |
       process -> state -> biology
                    |
       BoTorch 概率安全约束候选
                    |
             实验执行与回写
```

原始 Excel 只作为本地输入，不作为代码仓库资产。默认派生资产收敛为 `data/processed/mg2si.sqlite`。规范化表、全部子表原始行、映射、质量问题、训练视图、评估和推荐均保存在该数据库中，避免多个 CSV 产生版本漂移。

## 2. 数据实体

### Material master

每个材料/批次一行，保存材料组成、SHS 条件、表征信息、表面化学和筛选信息。关键身份字段为 `material_id` 和 `material_parent_id`。

### Cell long

每个样品-细胞系-浓度-时间-指标组合一行，保存 `sample_id`、`cell_line`、`concentration_ppm`、指标名、指标值、单位和 `source_sheet`。

### Stage long

保存原料、半成品 I、半成品 II 和成品等阶段记录。阶段数据用于理解材料流转和发现跨子表重复，不能在未经去重的情况下直接作为独立训练样本。

### BO record

BO 记录由材料身份、分支条件、可执行制备字段、实验条件和两个目标组成。推荐输出同时保留人类可读字段和模型数值编码字段。

## 3. 条件工艺分支

`workflow_branch` 是候选生成的硬条件，而不是普通的缺失值特征：

- `synthetic`：`synthesis_required=1`，必须提供 Mg/Si 比、合成温度、保温时间以及真空/压力条件；随后必须执行球磨和粒径筛选。
- `commercial`：`synthesis_required=0`，SHS 字段为 `not_applicable`；仍必须提供球磨时间、球料比和目标粒径。

候选生成器先选择分支，再在该分支允许的字段空间内采样。这样可以避免将商品原料错误地推荐为需要重新 SHS 的材料，也避免用统计填补制造不存在的工艺。

## 4. 映射与去重原则

映射优先级如下：

1. 规范化后的精确样品编号；
2. 明确登记的别名；
3. 层级或父样品别名；
4. 无法可靠判断时标记为 `unmatched`。

映射结果必须保留 `mapping_type` 和原始来源。TACE 汇总数据作为主训练来源；子表用于审计和补充来源信息，不与汇总表盲目拼接。

## 5. 目标定义

当前系统使用两个完整响应列，要求：

- 同一细胞系和实验条件下定义一致；
- 数值、单位和方向明确；
- 训练前只保留双目标同时存在的记录；
- 在代码中明确最大化或最小化方向，并在输出中保留原始目标名称。

模型按 `workflow_branch × tumor_cell_line × normal_cell_line` 隔离；任何范围样本不足都返回证据不足。

## 6. 可追溯输出

本地默认只输出 SQLite 数据库。`bo_training` 是数据库视图，不再物化为特征、目标和 joint 三套 CSV。阶段子表进入 `bioassay_source_audit`，与汇总不一致的记录进入 `source_conflict`。需要交换数据时再显式导出目标表。

## 7. 实验闭环

每轮 BO 的推荐应按以下顺序执行：

1. 检查候选的分支、工艺完整性和安全边界；
2. 由实验人员确认设备可执行性和样品编号；
3. 完成制备、表征和细胞学测量；
4. 将新结果按同一数据契约回写；
5. 记录模型版本、候选版本和实验批次后再进行下一轮训练。

模型推荐不直接替代实验安全审查，尤其不能把预测的生物性能当作安全结论。
